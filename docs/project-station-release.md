# R4：从教学实验转为项目代码服务站（2026-11-10）

## 产品纠偏

原主界面只提供三个教学样例，不能满足用户“在站内编写自己的项目并实时发现问题”的需求。新默认首页改为项目工作区；原教学实验移至 /?view=lessons，保留已有诊断、复测和学习记录。不是把三个例子改名为项目。

本轮已实现：创建和打开项目、添加多个文件/目录路径、切换编辑、服务端 SQLite 保存、保存版本冲突保护、刷新恢复、项目 JSON 导出、未保存离页提醒、Python 编辑停止约 650ms 后自动语法检查、错误行标记与跳转。检查取消和过期响应隔离避免旧结果覆盖新内容。

沿用 FastAPI/SQLite/CodeMirror；新 cm_projects 表增量创建，不写用户提供的路径到宿主文件系统。使用 Python AST 与 compile 进行语法有效性检查，编译对象不执行。接口按现有浏览器身份隔离，限定安全相对路径、30 文件、50 KB 项目内容；自动检查单文件最多 16000 字符。其他允许的文本文件可编辑保存，未伪称支持对应语法检查。

## 本轮测试与视觉

新接口测试先因接口缺失失败，再实现并通过。验证身份隔离、版本冲突、路径拒绝、多文件持久化、任意 Python 语法错误以及不会执行 raise 语句。
浏览器 26 passed（10.9 秒），包括桌面和手机的“创建项目—写两个文件—检出错误—修正—保存—刷新恢复”。原 24 项教学测试改用明确的教学路由后继续通过。TypeScript/Vite 构建通过。后端全量日志见 R4-test-evidence/project-pytest.txt；未发布的 causal_lab 研究测试不计入发布范围。

## 运行

本机最新预览：http://localhost:8770/ 。采用 localhost 避免和现有 127.0.0.1 实例 Cookie 共用，不停止用户的在线实例。
在新的部署启动目录按 docs/workbench.md 安装构建，启动 app.workbench:app 后默认即项目工作区。
旧实例若仍运行旧后端，无法使用新项目 API，需重启升级；教学路径 /?view=lessons 仍可使用。

## 真实性边界与后续主线

当前自动检查只覆盖当前 Python 文件的语法，并非全部逻辑错误检测；跨文件导入关系、未定义变量、第三方依赖均未分析。JS/TS/HTML/CSS 当前是文本编辑，不是完整 Web IDE。尚无项目导入、重命名/删除、终端、代码执行、Web 预览、部署或项目级 AI 审查。
项目按匿名身份保存，没有完善的登录恢复；应导出备份。JSON 导出尚无配套导入入口。项目总数和多用户生产负载仍需限额/性能验证。页面未设置假的 AI 审查按钮，不会自动发送项目代码或触发付费模型请求。

AIWeb 主线：以学生真实项目为载体，形成“编写—本地问题—AI 引用项目证据—修改差异审阅—复查—学习记录”闭环。不能仅以在线编辑器和模型聊天作为创新主张。
下一 P0：可恢复身份与备份导入；项目级只读上下文检索和 AI 审查；按文件/行号校验引用；修复建议 diff 审阅及版本绑定；受控的前端预览方案。
下一 P1：多语言静态分析、项目问题历史、从实际问题生成的复测、固定项目集 A/B/C 对照。AIWeb 官方评分对应须以完整规则复核为准，不把内部计划当成得分证明。
