# R9 独立评测与人工判读

holdout.json含16个新合成源码项目。冻结后的SHA256见reference/summary.json。开发者不得用这些案例修改提示词；如某例用于修复，应转入开发集并补充新独立样本。样本由开发助手编写，独立性指与R8开发回归案例分离，尚无外部盲评。

运行 `python tools/evaluate_studio_r9.py --output <新目录>` 验证预期行为。该脚本只运行仓库内合成样本的CPython参考结果，不连接模型；产品中的受限执行器仍单独报告不支持的语法。

真实模型结果必须逐例保存完整输入、响应、工具参数和结果、错误、模型标识、请求数、token和时间。原始结果只追加新目录。离线重放、模拟响应、确定性检查分别标注，不能增加真实模型成功数。

## 判读表

每个case_id填写以下字段，并链接原始响应及判读理由。判读对象包括explanation、全部hints、teaching和patches，不能只检查首条。

| 字段 | 计数口径 |
|---|---|
| protocol | accepted / rejected / provider-error，接受数除以所有已尝试案例数 |
| location | 对有确定错误的案例，文件及根因行匹配数除以该类已尝试数；解析器报告行可与根因行分别记录 |
| root_cause | pass / partial / fail / unavailable；pass除以所有已尝试数，另列可判读响应口径 |
| repair | pass / partial / fail / not-proposed / unavailable；有效建议数除以提出建议的案例数 |
| bad_repair | 至少一条错误修复的案例数除以提出修复建议的案例数 |
| correct_code_false_alarm | 正确代码上错误断言或无依据修改的案例数除以正确代码已尝试数 |
| cross_file | 引用来源正确、根因正确且任务完成的跨文件案例数除以已尝试跨文件数 |
| failure | provider、timeout、schema、citation、patch-safety、tool-limit等原始失败原因 |

修复质量应在可信测试环境核对普通、空值及边界输入的修改前后结果。有限测试通过只支持这些输入；业务需求不明确时保留条件性结论。输出缺失记unavailable，不能删除失败样本。独立样本16例之外，另运行R8三个已知错误的开发回归。

## 已授权并执行的真实评测方案

建议分两阶段，先3个已知错误开发回归，再16个独立案例和3个跨文件工具任务。每个工具任务最多3次模型请求，总计最多28次HTTP请求，重试0，temperature=0，每次最多2400输出token。模型建议使用官方deepseek-flash非思考模式，固定模型标识与服务地址，单次请求输入按保守上界计费并预留输出费用，累计预算上限人民币5元。模型与R8不一致时只能比较系统表现，不能把差异全归因于R9修改。

官方价格核读于2026-11-13，Flash高峰每百万输入token（缓存未命中）0.30美元、输出1.20美元。具体调用前需核对账户币种与实际模型配置，并实现请求前预算预留，预算不足即停止。来源 https://api-docs.deepseek.com/quick_start/pricing/ 。用户已明确授权，实际累计27次，保守预留1.328859元；原始记录见live-01和live-02。现有R8脚本硬编码旧42次账本，不适用于R9新额度。

运行入口为 `python -m tools.evaluate_studio_r9_live`。使用独立持久账本，重复运行沿用剩余授权，异常账本会阻止调用。最后1次余额没有自动使用。

## 实际结果与独立性边界

详细判分见 [语义报告](evidence/studio-r9/semantic-review.md) 及其 JSON。16 个独立案例的首次真实调用：协议 16/16，固定位置 10/11，根因或正确性 15/16，可应用补丁语义 5/8，含未确认契约的补丁 3/8，正确代码误报 0/4，直接跨文件 2/3。严格全文检查包括所有提示、机制、反例与补丁，原始模型 6/16，产品交付 7/16；它不能用根因指标替代。

另 3 个工具模式作业复用了跨文件样本：任务完成 3/3，但只有相对导入作业实际选择工具，使用 4 条调用、3 轮模型请求。没有新增独立样本。原始批次未出现超时或协议拒绝，内容错误、范围不完整及未知业务值仍是失败原因。

评测后 missing-branch-return 已用于补丁防护修复，转作开发回归。16 例首次成绩仍保留，但之后的同例重放不能再声称是独立验证；其余 15 例也不构成外部盲评。发布代码对 25 个保存回复的零网络重放见 release-offline-replay.json。该次重放移除了原始批次全部 4 份契约风险补丁，同时也移除了部分正确但无法受限验证的补丁。只剩 2 份语法修正补丁可进入用户审批，代价是自动补丁覆盖率下降；文字建议仍可能不准确。
